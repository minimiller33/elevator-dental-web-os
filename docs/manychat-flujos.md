# Manychat — especificación inicial de automatizaciones

**Responsable:** Zac, configuración de Manychat para los contenidos.
**Estado:** especificación en local; aún no hay flujos activos.

La configuración final depende del plan mensual y las piezas que prepara Héctor. No inventar fechas, palabras clave ni publicaciones antes de tener ese calendario. Confirmar en Manychat las capacidades y reglas vigentes para el canal elegido antes de activar.

## Flujo base por pieza de contenido

Duplicar este flujo por pieza/CTA y completar la ficha de configuración al final.

1. **Disparador:** comentario o respuesta con la palabra clave aprobada para esa pieza, solo en el canal conectado y con el disparador que permita la cuenta.
2. **Reconocer la solicitud:** enviar un mensaje breve que diga qué recurso se va a compartir.
3. **Consentimiento/elección:** ofrecer el enlace solicitado y una opción clara para continuar o terminar. Si el canal requiere una ventana o interacción válida, respetarla y no programar mensajes fuera de ella.
4. **Entrega:** mandar el enlace final aprobado con una frase contextual. No recolectar información clínica o sensible por DM.
5. **Calificación opcional:** preguntar ciudad/país y si desea conocer el proceso de una Elevator Web. Mantener ambas preguntas opcionales.
6. **Derivación:** si pide información comercial, ofrecer el formulario de brief o contacto aprobado. Si pide persona, marcar para seguimiento humano; no simular que un agente humano contestó.
7. **Salida:** permitir detener mensajes; detener el flujo si declina, solicita parar o requiere atención humana.
8. **Registro:** etiquetar origen, pieza, recurso solicitado y estado de consentimiento con los campos disponibles. La sincronización con CRM queda pendiente de que el equipo defina el CRM.

## Copy base (pendiente de aprobación)

**Primer mensaje**

¡Hola! Gracias por pedir {{recurso}}. ¿Te comparto el enlace?

**Entrega**

Aquí está {{recurso}}: {{enlace_recurso}}. Es un recurso informativo para explorar escenarios con los datos que tú ingreses.

**Pregunta opcional**

¿En qué ciudad está tu clínica? Puedes omitir la pregunta si prefieres.

**Invitación opcional**

Si quieres conocer cómo funciona una Elevator Web para una clínica, puedes completar este formulario: {{enlace_formulario}}.

**Solicitud de ayuda humana**

Claro. Dejo tu solicitud para que el equipo pueda responderte por el canal acordado.

## Datos que Zac necesita antes de configurar

- Acceso de editor a la cuenta oficial de Manychat y autorización para conectar el canal social aprobado.
- Canal y perfil que se usarán.
- Calendario y piezas aprobados por Héctor: URL de cada contenido, CTA, recurso y palabra clave por pieza.
- URL final del quiz/calculadora y del formulario.
- Texto aprobado, horario de atención humana y destino de las solicitudes de soporte.
- Confirmación de consentimiento y tratamiento de datos definidos por el negocio.
- Campos/tags requeridos por CRM, cuando se confirme cuál CRM usar.

## Ficha para cada pieza

| Campo | Valor antes de activar |
|---|---|
| Ciudad/mercado | Por definir según calendario |
| Canal y perfil | Pendiente de acceso |
| URL y fecha de publicación | Pendiente de Héctor |
| CTA y palabra clave | Pendiente de aprobación |
| Recurso y URL final | Calculadora local; URL pública pendiente |
| URL del formulario | Pendiente de destino/despliegue |
| Tags/campos de seguimiento | Pendiente de CRM y consentimiento |
| Responsable de atención humana | Pendiente de confirmar |

No activar mientras falte el canal, el acceso o las URLs públicas. Una vez disponibles, duplicar el flujo base por pieza, probar disparador, entrega, salida y derivación, y entonces activar.
